Space마다 문서 규칙, 팀 템플릿, 알림 채널을 정하는 방법입니다. 상위 문서: [[Clavis 사용 매뉴얼]]

사이드바의 **Space 설정**에 탭 세 개가 있습니다. 누구나 볼 수 있고, 바꾸는 권한은 다음과 같습니다.

| 탭 | 바꿀 수 있는 사람 |
|---|---|
| 문서 규칙 | 관리자 |
| 템플릿 | 편집자 이상 (모든 Space 공용 템플릿은 관리자) |
| 알림 채널 | 관리자만 (URL이 비밀이라 다른 사람에게는 탭이 보이지 않음) |

## 문서 규칙

편집 화면, 저장, 에이전트 API에 똑같이 적용됩니다.

- **규칙별 수준**: 끔 · 정보 · 경고 · 오류(저장 차단). 속성(frontmatter) 규칙은 오류로 고정입니다.
- 규칙을 **오류로 올리면** 그때부터 그 규칙을 어기는 문서의 저장이 막힙니다. 이미 저장된 문서는 그대로 남고, 다음에 저장할 때 고쳐야 합니다. **문서 상태** 화면에서 어떤 문서가 걸리는지 먼저 확인하세요.
- **유형별 필수 섹션**: 체크하면 이 Space만의 목록을 씁니다. 한 줄에 섹션 하나, `결정 | Decision`처럼 쓰면 두 이름 모두 인정합니다.
- **긴 문서 기준**: 이 크기를 넘으면 나누기를 권하는 정보가 뜹니다 (기본 50KB, 5~100KB).
- 설정을 바꾸면 **문서 상태** 화면이 열릴 때 모든 문서를 새 규칙으로 다시 검사합니다.

## 템플릿

새 페이지를 만들 때 고를 수 있는 팀 템플릿입니다. 기본 템플릿 7종은 항상 함께 나옵니다.

1. **새 템플릿** → 이름, 설명, 내용(Markdown). 문서 유형은 내용의 `type`에서 정해집니다.
2. **기본 템플릿에서 시작…**으로 기본 템플릿을 불러와 고칠 수 있습니다.
3. 자리표시가 만들 때 바뀝니다.

| 자리표시 | 바뀌는 값 |
|---|---|
| `{{title}}` | 페이지 제목 |
| `{{owner}}` | 만든 사람 |
| `{{date}}` | 만든 날짜 |

```markdown
---
type: meeting
status: draft
owner: {{owner}}
tags: [주간회의]
---

{{date}} 주간 회의.

## 참석자

## 논의 내용

## 결정 사항

## 액션 아이템

- [ ] 
```

- 템플릿도 이 Space 규칙으로 검사하며, 오류가 있으면 저장되지 않습니다.
- 템플릿을 지워도 이미 만든 페이지는 그대로입니다.
- 관리자는 **모든 Space에서 쓰기**로 전체 공용 템플릿을 만들 수 있습니다.

## 알림 채널 (Slack·Webhook)

이 Space의 문서·댓글 소식을 Slack 채널이나 다른 시스템으로 보냅니다.

### Slack 연결하기

1. Slack에서 알림을 받을 채널의 **Incoming Webhook**을 만듭니다 (Slack 앱 설정 → Incoming Webhooks → 채널 선택). `https://hooks.slack.com/services/…` 주소를 받습니다.
2. Clavis **Space 설정 → 알림 채널 → 채널 추가**에서 종류 **Slack**, URL을 붙여 넣고, **보낼 소식**을 고른 뒤 **추가**.
3. 카드의 **테스트 전송**으로 채널에 "✅ Clavis 알림 채널이 연결됐습니다" 메시지가 오는지 확인합니다.

> [!WARNING]
> Webhook URL은 비밀번호와 같습니다. 채팅·문서·코드에 붙이지 말고 이 화면에만 넣으세요. 저장 뒤에는 끝 네 글자만 보입니다. 유출됐다면 Slack에서 다시 만들고 교체하세요.

### 보낼 소식

| 소식 | 예 (Slack 메시지) |
|---|---|
| 새 문서 | `🤖 Adam · 새 문서 · [PAY] 결제 API 설계` |
| 문서 수정 | `🧑 toby · 문서 수정 · [PAY] 결제 API 설계 r5 · 변경 보기` |
| 휴지통으로 이동 | `🧑 toby · 휴지통으로 이동 · [PAY] 옛 문서 (하위 문서 2개 포함)` |
| 휴지통에서 복원 | `🧑 toby · 휴지통에서 복원 · [PAY] 옛 문서` |
| 새 댓글 | 문서 링크 + 댓글 앞부분 인용 |
| 댓글 해결 | `🧑 toby · 댓글 해결 · [PAY] 결제 API 설계` |

- 같은 사람이 같은 문서를 **5분 안에** 여러 번 고치면 Slack에는 한 번만 갑니다.
- 제목 변경으로 자동 수정된 링크는 보내지 않습니다.
- "변경 보기"를 누르면 그 수정의 차이 화면이 열립니다.

### 카드에서 할 수 있는 일

- **켜짐** 체크로 잠시 끄고 켭니다. 보낼 소식을 바꿉니다. 채널을 삭제합니다.
- **최근 전달**: ✓/✗, 소식 종류, 시도 횟수, 실패 이유.
- 실패하면 30초, 2분, 10분 뒤에 다시 보냅니다 (최대 3번). 같은 소식을 두 번 보내지 않습니다.

### Webhook (JSON)

다른 시스템에서 받으려면 종류 **Webhook (JSON)**으로 https 주소를 추가합니다. 카드에 보이는 **서명 키**로 받은 요청이 진짜인지 확인합니다. 형식과 서명 확인 방법은 [[REST API와 Webhook]].
